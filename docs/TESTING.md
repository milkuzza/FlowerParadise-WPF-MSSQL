# Проверка приложения

Проверено 29 октября 2026 года на Windows, .NET Framework 4.8, SQL Server Express LocalDB. **Все 16 проверок пройдены** на отдельной базе `FlowerParadiseVerification`. Также успешно собран Release через MSBuild: системный MSBuild 4.0 использовал установленные сборки .NET Framework, выдав предупреждения об отсутствии targeting pack и различии архитектур ссылок. Основной `Build.ps1` собирается без этих предупреждений. Для сборки в Visual Studio нужен .NET Framework 4.8 Targeting Pack.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Run-Tests.ps1
```

Скрипт собирает приложение и тесты, готовит проверочную базу, затем запускает операции MSSQL и формы WPF. Сборка не требует загрузки NuGet. При повторном запуске проверочная база должна содержать исходные данные: тесты временно создают и изменяют заказы, затем возвращают количества и суммы к контрольным значениям; последовательность новых ID может иметь пропуски.

Проверки отказываются работать с базой без слова Test или Verification в имени. Основная рабочая база `FlowerParadise` для них не используется. При аварийном прерывании используйте новое имя проверочной базы через `Run-Tests.ps1 -Database FlowerParadiseVerification2`.

## Автоматические сценарии

1. Количество записей, остатки и общая стоимость исходных заказов.
2. Вход, роли, неизвестный логин и отказ обычному пользователю в доступе к заказам.
3. Числовые и буквенные размеры, подписи единиц, исходные цены, товары с одинаковым названием от разных поставщиков и исправление пробелов в ключах.
4. Количество: корректное целое число и отказ для нуля, отрицательных, дробных, нечисловых и слишком больших значений.
5. Создание заказа из нескольких строк, изменение даты, сохранение исторической цены и возврат остатков при удалении.
6. Проверка прав на операции и отказ при подмене роли в объекте интерфейса.
7. Заказ менеджера на другого клиента, удаление строки администратором, запрет пустого заказа и повторного возврата остатков.
8. Изменение количества администратором, запрет менеджеру и клиенту, сохранение цены, откат при недостатке товара.
9. Полный откат заказа, если во второй позиции недостаточно остатка.
10. Запрет пустой корзины, отрицательного количества и устаревшей цены.
11. Ограничения внешних ключей, уникальности и положительного количества в MSSQL.
12. Два одновременных заказа последней единицы: успешен ровно один.
13. Загрузка и отрисовка всех встроенных XAML-форм.
14. Каталог гостя, совместные поиск/категория/сортировка, пустой результат, видимость функций по ролям.
15. События интерфейса: вход/выход, карточка, добавление в корзину, изменение/удаление строки, окно заказов, изменение даты и количества.
16. Финальная сверка остатков и суммы исторических заказов после временных изменений.

## Визуальная проверка

Изображения из `docs/screenshots/` получены от работающих WPF-форм. Каталог, карточка товара и окно администратора просмотрены: названия, суммы, изображения, размеры и кнопки отображаются без перекрытий при проверенных размерах окон. Пустые снимки отдельных форм с суффиксом View служат технической проверкой загрузки; иллюстрации с данными имеют имена catalog-*, product-live, cart-live, orders-* и login-live.

Тесты покрывают предоставленное описание предметной области. Отдельная проверка на другом компьютере, другой версии SQL Server и длительная нагрузка не выполнялись.
